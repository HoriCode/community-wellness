## Final Reflection

The structured prompt produced the most useful initial implementation because
it clearly described the target users, project features, technologies,
constraints, safety limitations, and acceptance criteria.

The zero-shot prompt was useful as a baseline, but it left many project
requirements unspecified. Few-shot prompting helped make the wellness
checklist content more consistent by showing Copilot the required format.

Role-assignment prompting helped identify accessibility and health-content
safety concerns. Structured analysis helped identify a technical issue and
provided a correction and verification procedure.

After applying the selected correction, I tested the checklist by checking
and unchecking items, using the keyboard, clicking the labels, and viewing
the page on a narrow screen. The final version was selected because it best
satisfied the project requirements.

I learned that AI-generated code and content must be inspected, tested, and
refined. A generated response or recommendation is not proof that the
website is correct. The developer remains responsible for verifying the
functionality, accessibility, safety, and quality of the final project.
